# Milestone F139: Projects keep Softfield's files in .softfield, not .softfield

> **State:** ready · **Priority:** 100 · **Area:** factory
> Planted by the owner on 2026-10-15.

## Notes
the .softfield folder should actually be .softfield. you'll need to update existing projects to work with that

## Plan (lead, 2026-10-27)
- **What it touches:** 1,326 mentions of `.softfield` in 94 tracked files outside the folder (runner, dashboard, prompts, docs, tests), and everything inside it (cards, ADRs, 73 ready tickets whose Context names `.softfield/…` paths). Three live projects carry the folder (Softfield, coucou, travel-companion), four forgotten test ones too. The database holds paths: 544 `jobs.log_path` (`.softfield/var/runs/…`), 93 planner proposals (12 still on a thread's last list), 14 tickets' `files`. And 25 open branches (`plan/*`, `task/*`) carry the old folder.
- **The approach: one move, done by the runner, not by hand.** Rewriting 1,300 lines in a lead ticket would cost a lot and miss some; and a branch that renamed the folder would be merged by the old runner, which then writes the ticket to `.softfield/tasks/done/` on a main that no longer has it. So a ticket builds `move_home` (D1–D4), a second wires it into the runner's start (D5), and the move itself happens on the machine, checked before it commits.
- **Softfield moves first, then the others:** Softfield's own move rewrites the runner's code, so the runner restarts on it (as after any runner/ change), and only that code moves coucou and travel-companion. A project that comes back later (a forgotten one) moves the first time the runner opens it.
- **What keeps the word "factory":** `factory_dashboard/`, `~/.config/softfield/factory.toml`, the `factory` area and the CSS classes (`.card.factory`, `.factory-status`). The folder is the tool's (like `.github`); the factory is the idea. Not asked to change.
- **No ADR:** AGENTS.md, the protected paths and `runner/instructions/` change only in the folder's name; no rule changes. The owner's approval of this plan covers it.
- **No mock-up:** the dashboard only shows the path in two places (a ticket's "Set aside" plate, the proposal's file list), and that is wording.
- Tickets: `f139-01-move-home` (lead: `runner/`, git and the database), `f139-02-runner-moves-projects` (lead: the runner's start and restart).

## Decisions
- **D1: `runner/home.py` owns the move.** `OLD = ".softfield"`, `NEW = ".softfield"`, and `move_home(repo: Path, conn: sqlite3.Connection, project: str) -> Moved | None`: None when `repo/.softfield` doesn't exist or `repo/.softfield` already does (nothing to do, or a half state it refuses to touch: said on the console and on the desk as an item for the lead). `runner/home.py` and `tests/runner/test_home.py` are the only files the move never rewrites, so they keep the old name.
- **D2: the main move, on a clean main, before any job.** In order: rename the folder on disk (`var/` and anything ignored go with it); in every tracked text file, replace `.softfield` where no letter, digit, `_` or `-` touches it on either side (`(?<![\w-])\.softfield(?![\w-])`, so `.card.factory` and `.factory-status` stay); `git config core.hooksPath .softfield/hooks`; run `check-all` on the result; commit as the runner (`Git.commit_all` with the runner's trailers and author, as `runner_commit` does: there is no session yet), "Softfield's folder moves to .softfield (F139)". If `check-all` fails, everything is undone (folder, files, hooksPath) and the desk says so with the failing check: main is never left half moved.
- **D3: open branches follow.** Each local `plan/*` and `task/*` branch not merged into main whose tree has `.softfield/` gets the same rename and text pass in a temporary `git worktree`, and one commit (no `check-all`: a draft or a blocked branch may be red already). `superseded/*` branches and tags stay as they are: they are the archive.
- **D4: the database follows, for that project only.** `.softfield/` becomes `.softfield/` in `jobs.log_path` (through its run's project), `planner_messages.proposals`, `tickets.files` and `tickets.body`, and the open `owner_items`' `text` and `command`. `planner_messages.text` is never changed: the owner's and the lead's words stay as written. One transaction, run after the main commit.
- **D5: when the runner moves a project.** In `run_projects` (`runner/loop.py`), before a project's `open_session`, and before its `project.toml` is read: if Softfield's own code still says `.softfield` (`config.PROJECT_TOML.parts[0] == home.OLD`), only Softfield's repo (`softfield_repo()`) is moved, then the runner restarts as after a runner/ change (`update_live`), on the moved code. Once the code says `.softfield`, each project with a `.softfield/` folder is moved when the runner first opens it. `softfield init` makes `.softfield` (its code is rewritten by Softfield's move, nothing to do by hand).

## Done (2026-11-02, terminal session)

So no self-restart and no lasting migration code: f139-02 was dropped, and the move's one-shot script was never committed. `superseded/*` branches and tags stay as they were. The four forgotten test projects have no folders left on disk.
