- Factory line: the data and every rule in Python, `factory_dashboard/line.py` (`live_line`, a JSON block in the page; `line.py` imports from `overview.py`, so `overview.py` imports `live_line` inside `_live_context`, never at the top); the drawing only in `factory_dashboard/static/factory.js` (hand-written SVG) → `tests/factory_dashboard/test_line.py` (tests on the JSON, plus one browser test: the page from `TestClient`, `/static/` from disk with `page.route`)

- Dashboard script with behaviour: `factory_dashboard/static/notify.js` (reads `data-` attributes a partial renders, acts after `htmx:afterSwap`; the facts are computed in Python) → `tests/factory_dashboard/test_app.py` (the attributes asserted from the HTML; one browser test replaces the browser API with a recording stand-in, `page.add_init_script`, and asserts what was called)
- A live part's 5 s refresh in a browser: `open_overview` and the two tests after it in `tests/factory_dashboard/test_overview.py` (`/` and `/live` rendered on every request, the database changed between polls, waits longer than 5 s)
- A panel drawn from the line document, with numbers you choose: `with_clog` and the four tests after it in `tests/factory_dashboard/test_overview.py` (monkeypatch `factory_dashboard.line.live_line` to call the real one and then set one key; the rule lives in a small function in `overview.py`, not in `line.py`)
- Dashboard colours and fonts: new UI uses the tokens, never raw colours. Pick from the `:root` block at the top of `factory_dashboard/static/dashboard.css` (`--floor`, `--bay`, `--plate`, `--rule`, `--hazard`, `--fail`, the agents' `--opus`, `--qwen`…, `--display`, `--body`, `--mono`); the light theme only redefines them, so a raw `#hex` stays dark in light mode. A mock-up's markup is a picture, not code to paste: map each of its `#hex` colours to the nearest token (f6-06 pasted them). E.g. the allowance meters: `.meter > .past-mark { background: var(--hazard); }` → `test_an_allowance_meter_says_how_close_it_is` in `tests/factory_dashboard/test_app.py` (`test_templates_use_the_tokens_never_raw_colours` fails a raw colour in a template)
- A button that asks the runner: `POST /requests` in `factory_dashboard/requests.py`, the dashboard's only write (one `owner_requests` row; never write anywhere else, and never through `Db`, which is read-only). The button is `hx-post="/requests"` with `hx-vals` for `kind`, `subject` or `value` and `project`; it swaps in `_partials/request.html`, which polls the request until the runner finishes it → `tests/factory_dashboard/test_requests.py` (send the `HX-Request` header and the client's own `Origin`; without them the route answers 403). Assert what a button posts, not that it exists: `_posts` in `tests/factory_dashboard/test_planning.py` parses its `hx-vals` as JSON, so a broken one fails (f6-08's had no closing brace and its tests checked only the button's id); a git checkout for the project is the `checkout` fixture beside it
- Asserting a page's text: Jinja escapes it (`'` becomes `&#39;`, so "the lead's" never matches the raw string), so strip the tags and `unescape` first, and assert within the item, not the whole page: `_text` and `_points` in `tests/factory_dashboard/test_planning.py` (f6-07 spent an attempt on an answer "missing" from the HTML)
- Showing part of a page on a phone: `factory_dashboard/static/deck.js` (toggles a class; the rule lives in `dashboard.css` under a media query, with `!important` because the points carry an inline `display`, which beats any stylesheet rule and the `hidden` attribute) → `test_on_a_phone_one_point_shows_at_a_time` in `tests/factory_dashboard/test_planning.py` (asserts what the browser draws with `is_visible()` and `bounding_box()`, never the `hidden` property or a selector like `[hidden=false]`: f6-10's test passed while all seven points stayed on screen)
- Counting what happened in a span of time: `queries.away` → `write_away` and the test after it in `tests/factory_dashboard/test_overview.py` (times are parsed with `_time` and compared as moments, never as ISO strings in SQL: the runner writes its own offset; the fixture is its own database in `tmp_path`, and each job has its own attempt)
- A count that must equal another module's: `live_line`'s five field counts from `board` (`factory_dashboard/line.py`, the import inside the function) → `board_counts` and `test_the_field_stations_count_the_board_s_cards` in `tests/factory_dashboard/test_line.py` (the test calls the other module on the same database and compares; never work a fixture's numbers out by hand first: f3-08 read for three attempts doing that and made no edit)
- A part of a page drawn again after a post: the `htmx:afterRequest` listener in `factory_dashboard/templates/planning.html` (`htmx.ajax` with `target` and `select`, never `fetch` + `replaceChild`: htmx must bind the new markup, or the new form's next send leaves as a plain GET; listeners go on the document, since the element they'd sit on is replaced) → `test_a_second_plant_adds_a_second_row` in `tests/factory_dashboard/test_planning.py` (send twice from the same page, and wait for something only the second re-fetch brings; "shows at once" is asserted on the page as it stands, never after `page.reload()`, which passes with no listener at all: `test_edit_then_save_posts_a_change_and_the_message_shows_it_at_once`)

## Notes
1. French says `vous` and sounds warm and plain: "Réessayez un peu plus tard", never "Veuillez réessayer".
2. Text lives where it's shown: `{% translate %}` in templates, `gettext("…")` with a literal in JS. JS French goes in `djangojs.po`. After editing a `.po` file, compile it with `msgfmt` (AGENTS.md rule 9).
3. If your new test passes before you change any code, the bug may already be fixed on main (f4-23: a finding fixed by two later tickets). Check the code the ticket names, then write `BLOCKED.md`: a first line that is exactly `CATEGORY: false-assumption`, then where main already does it. Don't rewrite the test to make it fail.
4. Test the edges, not only the middle: empty, one, many, the longest note (280 characters), just before and after midnight.
5. A UI test checks the layout at phone and display sizes: `layout_problems(page) == []` (`tests/browser/conftest.py`).
6. Browser tests stub the network with `page.route`, never a real server.
7. A command that writes data refuses to run in production.
8. Lines stop at 100 characters. Your finish line (`check-all --fix`) formats for you: it joins lines that fit, but won't split a long string (JS inside a Python test). Split only a string that's still too long.
9. Check `.factory/protected-paths.txt` before your first edit. If the task needs a protected file changed, don't try: write `BLOCKED.md` with `CATEGORY: needs-file` straight away.
10. Before writing an expected list from test data, open the fixture and follow its chain down to its root (`db_path` seeds rows too); never guess what it holds (f6-29 reasoned for an attempt about the threads `write_planning`'s docstring lists). Remember `runner.metrics` upserts: writing a row with an existing key updates it rather than adding one. If the count the test sees differs from yours, trust the page and recount; don't adjust the regex until it matches (f6-09 wrote "4 things" for three replies without finding the fourth, the fixture's ripe milestone).
11. If `all-tests` fails in a test about another ticket or a file outside your `files:` (f1-35: `test_tasks.py` naming f1-36), or `layout` names a file you never made (f13-01: a review's scratch file), main was red before you. Don't try to fix it: finish your own work and write `BLOCKED.md`: a first line that is exactly `CATEGORY: needs-file`, the failing test's or file's name on the next line.
12. When a number in your ticket disagrees with your count, write the rows out as a table (duration in seconds, each token column) and add them once; never change fixture rows or invent new ones to make a number fit. When your test and your code disagree, the ticket's Context decides which is wrong: never change an assertion that quotes the ticket to match your code (f8-06 posted `seven_day` where the ticket said `week`, then rewrote its test to agree).
13. A ticket that replaces a behaviour replaces its tests: rewrite the tests in your `tests:` that pin the old one, and never leave an assertion that can't fail. Keep them as narrow: an assertion within a panel that goes moves to the panel that replaces it, never to the whole page (f3-05).
14. `check-all` takes about 12 minutes. Run it with no `timeout` (the default is 15 minutes) and never a shorter one: f109-03 gave it 300000 twice, lost 10 minutes and learned nothing. "(no output)" after a shell timeout means the call was killed, not that the checks hang; never write `BLOCKED.md` for it.
15. To add to an existing file, Edit it, anchored on its last lines; never Write it: Write replaces the whole file (f2-07 wiped the 1,300-line dashboard `conftest.py` and lost the attempt). You can't delete or rename files, so create only those your ticket names: f3-16 made two empty ones and spent its last attempt failing to remove them.
