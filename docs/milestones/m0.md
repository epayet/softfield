# Milestone 0: Foundations (Claude only)

> ADR 00 was Accepted on 2026-09-27. Everything in M0 is built by Claude; the local model isn't used until the calibration run afterwards.

## Outcome

A repo where `uv run pytest`, every gate and `uv run runner --dry-run` pass. The pure event model and authorisation policy exist and are tested, and a first local-model task can be run end to end.

## Work items (in order)

1. **Project skeleton**
   - `pyproject.toml` (uv, Python 3.13), with these dependencies:
     - runtime: Django 5.2, channels, uvicorn[standard], cryptography, Pillow, PyYAML
     - dev: pytest, pytest-django, pytest-asyncio, hypothesis, ruff, mypy, django-stubs, import-linter, pytest-playwright
   - console scripts: `coucou-public`, `coucou-admin`, `runner`
   - `.env.example`, and the ruff and mypy config
2. **Settings**
   - `base`, `dev`, `staging`, `prod`, each with public/admin variants
   - SQLite WAL `OPTIONS`; `var/<env>/` paths; env-file loading; `COUCOU_PUBLIC_ORIGIN`
   - security headers and CSP
3. **Pure logic + unit tests**
   - `intake.py`: `EventType`, the `Event` dataclass, `validate_event`, `accept_decision` (idempotency)
   - `ordering.py`: `effective_at()` and `current_content()` (ADR 00 §2.5)
   - `ports.py`: repository, clock and ID Protocols
   - `authz.py`: the `Caller` (display or phone) and `can_read_space`, `can_post`, `can_react`
   - `reactions.py`: reaction-set validation
   - `pairing.py`: code and fingerprint formatting, expiry decisions
   - one unit test file per module (`tests/unit/test_<name>.py`)
4. **Models** (one Django app; `coucou/models/` split by topic; no views yet)
   - User (custom, email-less), Vault, Membership, Space (controllers, reaction set), Device (kind, SPKI, fingerprint, status, `revoked_at`), DeviceSession, `AuthGeneration`, Event
   - initial migrations
5. **Scoping + isolation tests**
   - `scoping.py` querysets derived from an authenticated device
   - two-vault fixtures; tests proving no cross-vault read or write at the queryset level
6. **Admin/public split**
   - `urls_public.py` (empty API namespace + health), `urls_admin.py`, and the two ASGI apps
   - tests: `/admin/` returns 404 on the public app; the public URLconf never includes admin
7. **import-linter contracts**
   - `pure modules`: the listed modules import only the stdlib and other pure modules
   - the public URLconf never imports `django.contrib.admin`
8. **Test fakes + contract tests**
   - `tests/fakes/` (repos, `FixedClock`, `SeqIds`, `MemoryMediaStore`)
   - repository contract suites run against the fakes and the ORM
9. **Runner + gates** (`runner/`)
   - task parser and validator; the dependency picker
   - git branch/merge helpers; pre-flight
   - OpenCode invocation (warm-up, context check, timeout)
   - each gate as a function returning `GateResult`, including the `layout` gate (one unit test file per pure module); attempts 1–3; escalation; BLOCKED handling
   - headless Claude invocation (env stripping, per-job tools, usage-limit pause/resume)
   - `workflow/runner.toml` (caps, timeouts); run logs in `var/runs/`
   - `--dry-run` and `--once` modes
   - runner unit tests (a fake git repo, fake subprocesses)
10. **systemd templates** (`deploy/systemd/`)
    - `coucou-public.service`, `coucou-admin.service`, `coucou-funnel.service`, plus an install README
    - **not installed**
11. **Staging**
    - the `staging` settings; a `uv run coucou-staging` helper that runs both processes on alternative ports
    - one e2e smoke test (health + `/admin/` returns 404 publicly)
12. **Report:** `docs/reviews/m0.md`. Then stop for the owner's sign-off.

## Done when

- All gates pass on `main`; the runner's own tests pass; `runner --dry-run` lists no tasks and exits cleanly.
- Isolation tests exist for every model-level scoping helper.
- The owner signs off M0.

## Then: calibration

Write 1–2 small M1 tasks (e.g. an admin registration for `Vault` and `Space`, and a `seed_demo` management command), run the full pipeline with the local model, and report on attempts, gate failures and timing, with sizing and context recommendations.
