## Sign-off sheet

### 1. What changed
- **The factory has a dashboard:** `uv run runner dashboard` serves `http://127.0.0.1:8765`: Overview (Needs you only when something does, Running now live, the queue, Claude's allowance, savings), Milestones, Tickets, Jobs, Runs, Timeline, Agents, Bench and the project page. Each item has its own URL.
- **Every run writes to one metrics database** as it happens, M1–M4 included (`runner backfill`), and `uv run runner report <key>` writes a review's numbers in dollars.
- **The runner is allowance-aware (ADR 15):** it reads Claude's 5-hour and weekly windows from its own jobs, keeps 30% of the week as a reserve and asks before using it, parks a job stopped by a limit and goes on with other work, and resumes after a Ctrl-C or a crash.
- **Agents and routing:** agents and roles live in `workflow/runner.toml` (local Qwen, six Ollama Cloud models, Sonnet, Opus, Copilot). A router picks who does a developer ticket and steps up after a failure. Retries build on the branch, and an escalation can `finish` the work. Copilot shadows checkpoints. `runner bench` replays a ticket for any agent. "Junior" is now "developer", and tickets carry a difficulty.

### 2. How to test it yourself
1. `uv run runner dashboard`, open `http://127.0.0.1:8765` on the desktop, then again at phone width (the browser's device mode: it only listens on the desktop).
2. Overview: with no run going, Needs you shows only real items (for now: M4's sign-off and F1's). Open F1 under Milestones: outcome and Done when first, then the numbers.
3. Open any ticket from the F1 page (f1-34 is a good one: 8 attempts), then one of its jobs, then its run: the breadcrumbs go back up.
4. Agents: each agent's jobs, cost and rating history; Bench: the empty grid until a bench runs.
5. `uv run runner report f1`: the numbers in `docs/reviews/f1.md` refresh.
