## What was built

| Area | What exists now |
|---|---|
| Protocol core | `coucou/deviceauth.py`: challenge messages, P1363 → DER conversion, strict P-256 SPKI loading, token hashing and TTLs (nonce 60 s, session 1 h). `coucou/pairing.py`: Crockford codes, fingerprints, rate limits (5/min, 20/day, 20 pending) and `client_ip`. |
| Models | `AuthChallenge` and `RegistrationAttempt`. `Device.kind` is blank while pending. Only one non-revoked device per public key (migration 0003). |
| Sessions | `DeviceSessionMiddleware` re-checks the session on every request. Writes need `Origin` + `X-Coucou: 1`. It records `last_seen_at` at most once a minute, switches to the device's language (via `pick_language`) and sends a CSP. The cookie is `__Host-coucou_s` + `Secure` in prod, and `coucou_s` only on plain localhost (ADR 03 item 2). |
| Public API | register, challenge, status (signed), verify → cookie, `me`. Errors are stable codes, and unknown and revoked devices look the same. |
| Admin | **Claim a device:** enter the code, check the fingerprint, then pick a space (display) or a person (phone), with a label and a language. A code works once. A claim loses a race with a revoke. It refuses revoked, active and expired devices, and ones with an empty key or code hash (closes m1-F4). Revoking a pending device kills its code. |
| Client JS | A non-extractable P-256 key in IndexedDB. Pairing: register, show the code, poll every 3 s, then redirect. Sign-in is retried once on 401. A dev-only vector page. |
| Pages | `/` pairs any device and then redirects by kind. `/display/` and `/phone/` show "all set" pages. English and French, `vous`, kind-neutral. |
| Static files | WhiteNoise in the public process, serving only `collectstatic` output collected under the public role (after m2-F1). |
| Workflow (ADR 04) | The model may run `msgfmt`. `BLOCKED.md` categories are read from the first `CATEGORY:` line. OpenCode timeouts kill the whole process group. |

### French check

The local model's French (m2-02, m2-03), and headless Claude's for m2-01:
- **Correct:** accents are all there, `vous` throughout, typographic spaces before `:` and `!`.
- **Reworded in m2-05:**
  - "Veuillez patienter…" and "Veuillez réessayer…": stiff, formal-letter French.
  - "Nous continuons d'essayer": who is "nous"? The device keeps trying.
  - "Quelque chose s'est mal passé": a calque of the English.
  - "Vous êtes connecté !": masculine, on a phone that belongs to a person, and Mum and your sister will read it.
  - "envoyer des moments d'ici": can read as "from now on".
  - "Chrome ou Safari à jour": clumsy.
  - "Tout est configuré !": technical. It becomes "C'est prêt !".
- **Kept:**
  - "Connectons cet appareil"
  - "Le code est valable 10 minutes."
  - "Obtenir un nouveau code"
  - "Ce code a expiré."

## Workflow observations

- **UI tasks, once the tooling was right: 3/3 on the first attempt,** in 1.3–2.2 min of model time, with no gate failures. m2-01's escalation was a tooling gap: the model wasn't allowed to run `msgfmt`, and it wasn't the model's fault. ADR 04 closed that gap.
- **Experiment (outcome vs dictation):** outcome-style m2-03 and m2-04 passed first time in 131 s and 77 s. Dictation-style m2-02 also passed first time, in 129 s. m2-01 can't be compared (tooling). With this few tasks, spec style made no visible difference. Both styles work for small UI work when Context pastes the skeleton.
- **The review's value was in what the tests couldn't see:** an ADR drift (F1), a UI dead end (F3), and a test that passed without testing anything (F4). All three were in Claude-written protected code, not the local model's. Lesson for my own work: when a test depends on a fixture someone fills in later, make it skip visibly, not pass.
- **French still needs a human-quality pass every time.** The model gets the accents and `vous` right when the spec says so, but it translates word by word ("Veuillez", "Quelque chose s'est mal passé"). Its French could be closer on the first try if specs included one line of tone examples ("Réessayez un peu plus tard", not "Veuillez réessayer plus tard").
- **This review job's tools:** it couldn't run `msgfmt` or delete files, so a two-minute French fix became a local task. That's cheap, but it costs a review round. If French fixes keep coming, allowing `msgfmt` in the review job would save the round (a workflow change, so it would need an ADR).
- **Headless Claude runs for M2 so far:** 3 of 10 (1 escalation and 2 review rounds).
- **Round 2:** the French fix passed on the first attempt. It was a verbatim-text task: an exact `msgid` → `msgstr` table plus a failing test. That's the cheapest kind of local task, and it confirms that routing wording fixes to the local model works. It still costs a review round, though.
- **This round's tools:** Bash was denied, so I couldn't run git, pytest or `msgfmt -c`. Instead I read the files and the runner's gate log (`var/runs/…/m2-05-french-wording/gates-1.txt`). That was enough for a text-only diff. A code fix in round 2 would need test access to be verified properly.
