Pre-flight collects backticked paths in Context and requires every `class`/`def` pasted there to be defined in one of those paths or in the task's `files:`. The spec named the model files only inside `# coucou/models/...` code comments, which pre-flight doesn't count as paths. ### What the model did well

- **Zero exploration:** it read exactly the files named in the task (4 reads for m1-01, 3 for m1-02) and nothing else. The pasted Context was enough, which is the most important calibration result.
- It followed Steps literally and correctly, including the mypy-motivated `isinstance(value, Sequence)` guard and the security rule (the demo display stays pending, with no key or pairing code).
- When `ruff check` flagged a long line, it fixed it and re-ran the tests on its own.

### What it did badly

- **Retry blindness:** on m1-01 attempt 2, the gate output said ruff failed on `tasks/ready/m1-01-….md`. The model ran ruff on *its own* files, saw them clean and replied "all gates pass". It never wrote `BLOCKED.md`. With a rule like "gate failed on a file outside `files:` → BLOCKED needs-file", it would have escalated after 1 attempt instead of 3 (ADR 01 item 3).
- **Never ran mypy** in any of its 5 attempts, even though Steps asked for it. It gets pytest and ruff from the fixed prompt, and seems to weigh that over the task's Steps (ADR 01 item 3).
- **Literal-minded:** told to report whether "anything was created", it tracked only the objects it had assigned to variables, which missed memberships and the display. The tests didn't pin that case either, which is on me. I fixed it directly and added a test.
- Added `# Create vault`-style comments the codebase doesn't use (a nit, removed).

### Mistakes on my side (and what I'll do differently)

1. **Python snippets in a spec must be ruff-formatted.** Ruff formats code blocks inside Markdown, and a gate failure on the task file is unfixable for the model. I now run `ruff format --check` on the spec before committing, and it caught the same problem in m1-02.
2. **Backtick the full source path of every pasted signature**, and never a bare filename (`__init__.py`). Pre-flight builds its search list from backticked paths.
3. **Skeleton tests should pin every branch the Steps describe** (the "nothing changed" message).
4. **Skeleton-first clashes with the `all-tests` gate** when more than one task is queued. I queued the two tasks one at a time and wrote this up as ADR 01 item 1. M1 proper needs it.

### Suggestions for M1

- **Task size:** these tasks were 10–40 changed lines and well within reach. Try M1 tasks of **60–150 lines** at the same Context density (exact signatures, expected values listed in prose, the model's fields pasted). Keep one concept per task. Watch the per-step input, which should stay under ~20k.
- **Context:** keep pasting signatures and "what the tests check" lists. That's what made zero exploration possible. Also paste the relevant *model fields* rather than referring to a file.
- **Prompt:** add mypy and the BLOCKED rule for out-of-scope failures (ADR 01 item 3).
- **Process:** don't edit the working tree while the runner runs. It does `git add -A`, so any stray file becomes part of the task's diff. Today another session left uncommitted files (committed on your say-so), and I nearly dropped an ADR draft into the tree mid-run.
- **Optional tool:** `runner check-task <file>` = pre-flight plus a formatting check, for me to run before committing a spec. It's a tool, not a rule change.
